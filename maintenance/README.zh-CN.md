# Windows 汉化维护

本分支维护 javaht/claude-desktop-zh-cn 的 Windows 简体中文适配。上游项目及许可证保持原样。

## 分支和日常使用

- `main`：上游镜像，每 6 小时由 GitHub Actions 尝试快进同步（计划为香港时间 02:17、08:17、14:17、20:17，GitHub 可能延迟）。发生分叉时停止并报错，绝不强推。
- `katou/windows-compat`：默认维护分支，保留本机已验证的兼容修复。上游新代码通过 PR 审阅、测试后再合并。
- 本地检出目录为本仓库所在目录，远程 `origin` 是个人 Fork，`upstream` 是原项目。

需要重新安装时，在本分支运行原项目的 `install-windows.bat`。安装会关闭并重启 Claude，按原安装器要求处理管理员授权。安装前先检查本机版本和 `compatibility.json`；未验证的新版本先检查结构和备份，再安装验证。定期检查不会关闭 Claude 或自行安装。

## 当前修复

Windows Code 页可由宿主把语言重新设为 `en-US`，仅写 `config.json` 不足以解决。本分支在资源打包前，把独立语言状态的初始值和英文回退值设为 `zh-CN`，保留其他语言的覆盖行为。修复通过唯一结构锚点匹配，不依赖完整 bundle 文件名；重复应用保持不变，未知或重复锚点会拒绝处理。

同时补入“Code 设置”“绕过权限”两个词条。沿用原项目的备份、ASAR 重建和程序内嵌哈希更新；Cowork 服务二进制保留原样，Cowork 功能尚未验证。修改 Claude.exe 仍会使其原有签名失效。

## 已验证范围

2026-11-10 在 Claude 4.23118.1 上重启观察到“新建、搜索、自定义、终端、文件、Code 设置、环境、权限”等中文控件。6,037 个 ASAR 条目完整性检查、417 个修改后 JavaScript 文件语法检查通过，CC Switch 供应商配置与安装前一致。少量新标签、斜杠菜单说明仍为英文。

REA 静态分析针对安装包中的语言模块；项目安装流程直接依据完整源码审阅。详见 `rea-summary.json`。REA 的静态关系不能单独证明运行时效果，界面结论来自实际重启后的检查。

### 自动维护如何运行

- **云端获取更新**：`track-upstream.yml` 在电脑关闭时也可运行，仅快进镜像，比较正式 Release 与未发布的 main，出现待审改动时创建或更新一个草稿 PR。每次保留 14 天的精简元数据报告，不上传应用文件或用户数据。没有新提交时不创建 PR、不反复编辑已有内容；机器区块之外的审阅说明保持原样。
- **Codex 审阅整合**：现有每日检查继续核对本机版本、语言资源、同步工作流、分支保护和待审 PR。你已授权自主维护仓库；代码审阅和相关测试完成、Windows/Linux 必需检查通过后，可通过受保护的 PR 整合。词库冲突只在能确认键值一致时解决，复杂或未知冲突保留待审。此过程需要 Codex 本机检查能运行，GitHub 云端镜像不依赖本机在线。
- **测试状态据实记录**：GitHub 内置令牌的推送不会自动触发后续 CI；创建或更新 PR 时，工作流可能进入待批准状态。云端草稿只表示发现更新，不能算测试通过；Codex 审阅后可批准必要的测试，或推送已审阅整合分支，核对两平台结果后再合并。见 [GitHub 官方触发规则](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/trigger-a-workflow)。原有本机 Linux 符号链接权限限制单独记录，不更改系统权限来让测试变绿。
- **权限与失败处理**：云端令牌只给当前同步作业仓库内容和 PR 写入权限；工作流不调用审批或合并接口，保护规则不允许绕过。仓库需允许 Actions 创建 PR（GitHub 的设置同时命名为允许创建和审批）。同步失败立即停止后续写操作，下次计划重试；Codex 发现失败或超过 30 小时没有有效运行时调查/恢复，不修改 main 历史。GitHub 可能延迟计划，长期无活动也可能暂停计划，不能保证精确时间。
- **客户端保持独立**：仓库同步不等于应用汉化安装。未知版本、未知锚点不试装；不关闭 Claude、不自动安装补丁、不修改自动更新，不读取 CC Switch 数据库、密钥、聊天记录和原始日志。
- **减少无关失败**：Fork 未配置文档站，继承的 Pages 部署工作流在本 Fork 停用；上游本身不受影响。汉化回归测试和同步任务继续启用。

### 日志与记录管理

- 云端追踪报告只允许状态、版本、提交、计数、可信仓库链接、UTC 时间、运行编号和稳定指纹。失败只写固定错误码，不写原始异常、命令输出、环境变量或私人路径；命令超时也以失败状态退出，不能伪装成功。令牌只在追踪步骤中提供。
- 仓库的 Actions 日志及检查/运行元数据保留 30 天，追踪 JSON 附件单独保留 14 天。设置通过 [GitHub 官方保留期限接口](https://docs.github.com/en/rest/actions/permissions#set-artifact-and-log-retention-settings-for-a-repository) 管理；调整期限不表示已追溯删除历史记录。未进行批量删除。
- 本机状态仍保存在忽略目录 `.maintenance/tracking-state.json`。每次检查更新状态后，在仓库目录执行 `python maintenance/run_records.py --state .maintenance/tracking-state.json`。它只从该维护状态提取允许的字段，以原子写入保存到 `.maintenance/records`，保留 30 天且最多 120 份；仅清理本工具规定文件名的记录，拒绝重定向目录，不清理任何备份、不认识的文件或 Claude 日志。保留期限在成功写入记录时执行，离线期间不会另起后台清理任务。
- 现有 Codex 本机检查计划为香港时间每天 09:30；云端每 6 小时获取上游。日常检查核对任务是否重复、工作流是否启用、超过 30 小时是否没有有效运行、分支保护及保留期限是否发生变化。恢复任务后先实跑验证，不通过停用测试、绕过保护或无意义提交消除告警。

### 同步与安装步骤

1. 查看上游 Release、`main` 与维护分支的差异，创建或更新 `main` → `katou/windows-compat` 的待审 PR。
2. 先运行项目回归测试及 `tests/test_windows_locale_preference.ps1`，核对语言模块锚点。上游若已有等效修复，优先采用上游实现。
3. 备份新版本原始文件；保持 CC Switch 接口、密钥和供应商不变。安装并重启验证后更新兼容性记录。

本机原版文件、CC Switch 数据库、配置、安装日志和完整 Claude bundle 保留在本机，不提交到此公开仓库。Claude 自身更新后会换用新的程序包，需要重新验证和安装汉化。GitHub 定时任务可能延迟，Fork 的长期无活动任务也可能被平台暂停；本机定时检查会一并检查工作流状态。
